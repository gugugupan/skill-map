## 归纳取舍

- 43 个能力点，7 个类别（frontend-found / framework / ui / quality / eng / fullstack / ai）。
- 复用现有 50 个里的只有 `agentic`（描述「生产级深度使用 Claude Code、Codex 等工具」对前端同样成立；Stripe、Vercel、Notion、百度等都要求）。
- 预定通用 slug 用了 10 个：web-basics、ts、git-collab、testing、ci-cd、perf、observability、api-design、security-basics、prompt-eng，均写了完整内容（前端视角，merge 时可挑更通用的版本）。
- 没复用 `state`（Agent 会话状态）→ 新建 `fe-state`；没复用 `net`（描述是 Agent 流式/出口控制）→ HTTP 知识放进 `web-basics`；没复用 `llm`（描述是 Agent 平台语境）→ AI 部分只保留 `prompt-eng` 和新的 `streaming-ui` / `ai-ux`；没复用 `cache`（预定为后端缓存，Redis 等）→ 新建 `http-cache`（浏览器 / CDN / Service Worker）。
- `perf` 写成通用方法论（测量→定位→优化→防回归），前端特有的拆成 `web-vitals`（加载）和 `render-perf`（运行时/内存）。
- 未单独成点：Docker/K8s/AWS/Terraform（PayPay、みらい翻訳 技术栈里有，但不是前端职责核心）、Harness Engineering（阿里 ATH/PDEE 提到，属 Agent 语境）、产品思维/沟通（软技能）。
- 先修 60 条，无环，无现有 slug 之间的边（唯一复用的 agentic 只作为终点：git-collab → agentic）。
- path 5 阶段 33 个能力点。
