## 归纳取舍

- **复用的现有 slug（8 个）**：`lang` `os` `net` `dist` `k8s`（契约点名的通用 slug）；`tenant`（概念「计算、网络、数据隔离、噪声邻居」对 SaaS 多租户同样成立）；`agentic`（几乎所有 JD 都要求日常用 AI coding 工具，与「深度使用 coding agent」一致）；`llm`（网易、Datadog 要求后端理解模型 API，概念「function calling、上下文窗口」通用）。这 8 个只写 slug/cluster/companies，不改内容。
- **没有复用 `conc`**：它的概念是模型限流和租户公平，不是线程/锁，另起 `concurrency`。**没有复用 `gateway`**（LLM Gateway），另起 `api-gateway`（7 层流量网关）。**没有复用 `trace`/`sre`**：用预定通用 slug `observability` 和 `incident`。**没有复用 `cpdp`**：美团网关岗提到数据面/控制面，但只有 1 家，放进 `api-gateway` 的 concepts。
- **预定通用 slug（18 个）**都写了完整内容：sql-db nosql cache mq api-design auth testing ci-cd git-collab docker cloud iac observability perf security-basics sys-design data-modeling incident。
- **新 slug（19 个）**：dsa cpp jvm concurrency oop-design net-programming web-framework microservices api-gateway db-scaling search-engine resilience dist-txn stream-processing ddd progressive-delivery tech-lead ledger risk-systems。
- **语言拆分**：`lang` 只覆盖 Go/Rust/Python；中国 JD 大量要求 Java（美团、网易、PayPay）和 C++（腾讯全部 4 份），所以单独做了 `jvm` 和 `cpp`，而不是把 Java/C++ 塞进 `lang`。
- **领域能力点**：`ledger`（账务与资金正确性）和 `risk-systems`（风控与合规）来自样本里金融/支付岗位较多（Stripe、Coinbase、Robinhood、PayPay、Money Forward、微信支付）。它们是「后端常见业务领域」而非通用基础，所以不放在前 5 个阶段，放在最后一阶段。
- **先修**：58 条，无环，没有两端都在现有 50 个 slug 里的边（只有新→旧或旧→新，例如 `docker→k8s`、`sys-design→tenant`、`api-design→llm`、`os→docker`）。path 6 阶段 32 个能力点，阶段顺序满足先修。

## 不确定处

- **AI 色彩偏重的样本**：2026-11 的中国后端 JD 里 AI 相关职位比例很高（腾讯列表里一半是 AI 后台）。我刻意挑了通用后端岗位；网易 Codewave 岗是「AI 网关 + 流量网关」，主要用它支撑网关、JVM、Netty 证据，`llm` 的热度只有 2，可以考虑在 merge 时去掉。
- **ByteDance、阿里没有拿到**：字节的招聘 API 需要 CSRF token，这次取不到，就没收。中国只有 3 家（腾讯、美团、网易），在 3–4 家的目标范围内。
- **日本只有 2 家**（PayPay、Money Forward），在 2–3 家的目标范围内。Mercari、SmartNews、LayerX 等在 Greenhouse/Lever/Ashby 上没有公开 board。两家都是金融科技，所以日本样本偏金融。
- **美团链接**：正文来自 `zhaopin.meituan.com/api/official/job/getJobList`；职位页 URL 按站点的 `web/position/detail?jobUnionId=` 格式拼出，curl 返回 200（SPA 外壳），但没有在浏览器里看到渲染后的正文。
- **技术栈 vs 要求**：PayPay、Money Forward 的部分证据来自「Tech Stack / 利用中の技術」列表（如 TiDB、ELK、Terraform、Jenkins、JUnit），不是「必须要求」。`iac`（只有 MONEYFORWARD）和 `search-engine` 里的 PAYPAY 证据都属于这种情况，已在证据表中标注。
- **`dist-txn` 和 `ledger` 有重叠**：前者是技术手段（幂等、Saga、Outbox），后者是金融领域（复式记账、对账）。merge 时如果其他岗位也有类似点，可以再考虑合并。
- **`db-scaling` 证据偏弱**：腾讯（HTAP 查询）、网易（「分布式数据库」）、PayPay（TiDB 技术栈）、Coinbase（分布式数据存储）都没有直接说分库分表。
- 资源 url 都是已知的官方文档或经典文章地址，这次没有逐个 curl；书籍没有 url。
