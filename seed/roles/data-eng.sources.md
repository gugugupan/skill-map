## 归纳取舍

- **复用**：`dist`（概念是共识、幂等、exactly-once、DDIA，对数据工程成立）和 `agentic`（深度使用 coding agent，对 JD 里的 "AI 辅助开发" 成立）。`lang` 的内容是 Go/Rust 和 asyncio，不复用，改用预定 `python` 和新点 `jvm`。`os` 的内容是 namespace/cgroups/沙箱，不复用，另起 `linux-shell`。`k8s`、`sre`、`cost`、`rag`、`llm` 的描述都写的是 Agent 语境，没有复用；`cost` 讲的是 LLM 调用成本，数据侧另起 `data-cost`。
- **预定通用 slug 写了完整内容**（契约要求第一个用到的岗位写全）：python、sql-db、data-modeling、git-collab、mq、nosql、ci-cd、testing、observability、incident、iac、docker、cloud、api-design。合并时从各岗位里挑最好的一份。
- `data-modeling`（通用的概念/逻辑/范式建模）和 `dim-modeling`（Kimball 维度建模）拆开，因为美团明确把「范式建模、维度建模」并列。
- `observability`（服务监控）和 `data-observability`（新鲜度、体量、分布、数据 SLA）拆开，数据 JD 讲的多是后者。
- 合并的点：增量处理和幂等放进 `etl-elt`；CDC 放进 `data-integration`；Parquet/ORC 列式格式放进 `lakehouse`；Presto/Trino 放进 `olap`；数据安全、脱敏和合规放进 `data-governance`。
- 先修边控制在 60 条：去掉了几条两端都是预定通用 slug 的边（python→testing、cloud→iac 等），以免替其他岗位先定死它们之间的关系。保留了 sql-db→data-modeling 和 docker→ci-cd 两条。`nosql`、`iac` 在本岗位没有边。

## 不确定处

- **排除的 JD**：Coinbase "Staff Data Engineer, Market Data" 实际是低延迟行情系统（feed handler、Aeron、FIX），更像后端岗，没收。Woven 伦敦的 Data Infrastructure 岗不在日本，没收。LINE 雅虎「データエンジニア / 事業横断」页面显示募集終了。Mercari 的 Greenhouse 看板 `boards/mercari` 返回 0 个职位，官网是 JS 渲染，没有取到 JD。
- **日本只有 2 家**（PayPay、Woven）。PayPay 这份偏数据平台基础设施（Terraform、Databricks 运维），Woven 这份是障碍者雇用岗、发布于 2024-03（2026-11 仍在 Lever 上架）。它们贡献的主要是 lakehouse、治理、云和 IaC 证据。
- 美团职位页链接用的是 `zhaopin.meituan.com/web/position/detail?jobUnionId=…&highlightType=social`，curl 返回 200，但页面是 JS 渲染，正文是从列表 API 取的。阿里链接去掉了 track_id 参数。腾讯链接用 API 返回的 PostURL（改成 https）。
- 中国 JD 普遍把「Data Agent / NL2SQL / AI 辅助开发」写进职责，美国 JD 较少提到。`data-agent` 的热度主要来自国内。
- 一些公司归属是轻度要求：COINBASE→agentic（"AI tool experience"）、CHIME→data-observability（"key metrics for data pipelines… visibility"）、A→metrics-layer（阿里健康 "语义建模"）。
- 资源 url 只填了能确认的官方文档或知名链接。书名类资源（Kimball、FDE、DMBOK、Streaming Systems 等）省略 url。"Kleppmann《Designing Data-Intensive Applications》" 与 vocab 里的标题一致，没有 url。
