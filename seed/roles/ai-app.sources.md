## 归纳取舍

- **岗位边界**：只收「用 LLM 做产品功能」的 JD。排除了 Agent Runtime / 推理 / 平台类职位（如腾讯「微信-AI应用开发工程师」实为 Agent Runtime 与 Checkpoint 基础设施；Perplexity Inference；Harvey/Decagon AI Platform；Sierra Agent Runtime），这些属于 agent-infra。Intercom「Senior Product Engineer, AI」读过正文，但偏传统 ML 产品化且明说不需要 LLM 经验，美国已凑满 5 家，未收。
- **复用（16 个）**：llm、tools、gateway、rag、memory、ctxeng、loop、patterns、multi、durable、hitl、evals、trace、guard、cost、agentic。逐个读过 vocab 描述，内容在应用语境同样成立。
- **预定通用（14 个，写了完整内容）**：python、ts、web-basics、api-design、sql-db、cache、mq、sys-design、testing、docker、cloud、observability、prompt-eng、embedding-search。
- **新增岗位能力点（15 个）**：llm-api、structured-output、multimodal、fine-tune、doc-parsing、llm-workflow、streaming-ui、gen-ui、ai-ux、mobile-llm、ab-test、data-flywheel、product-sense、proto、biz-automation。
- **没收的**：混合检索 / 重排没有单独成点，因为现有 `rag` 的 concepts 已含「向量、BM25 与混合检索」「重排序」，Ubie 的 Agentic Search、Perplexity 的 retrieval and ranking 都记到 `rag`。`mcp`、`inject`、`security-basics` 在所选 JD 正文里找不到明确要求，没收进来（避免无证据的 companies）。
- **先修**：56 条，全部至少一端是新/通用 slug，没有两端都在现有 50 个里的边；无环。全部边两端都在本岗位内。
- **path**：6 阶段 32 个能力点。
